# 填表評測：1.7B 模型沒有專用 function 時能不能替民眾填表

想知道的事：之後遇到新的表單（沒有人替它寫過規則或專用工具），手機上的 1.7B 模型能不能只靠表單欄位清單，從民眾的原話把表單填好？如果不行，要怎麼補？

**結論**：只靠模型不行，新表單大約七成欄位對、整張全對只有一成到兩成，而且會自己填上沒說過的值。加上一層**按欄位型別**而不是按表單寫的確定性防護 [`form-guard.ts`](../src/agent/skills/form-guard.ts) 之後，在**從沒看過的題目與一張全新的表單**上（手機 LFM3 1.7B）：

- 欄位正確率約 89～96%，整張全對 42～83%。
- 捏造從 7/10、11/14 降到 0。
- 提示注入不再成功。
- 也比替表單手寫的專用 function 準。

新表單只要宣告欄位清單，就能套用。

- 程式：[`form-fill.ts`](../src/agent/skills/form-fill.ts)（`fillFormGuarded`）、[`form-guard.ts`](../src/agent/skills/form-guard.ts)
- 評測：[`tests/form-fill.eval.ts`](../tests/form-fill.eval.ts)；保留題：[`tests/form-fill-heldout.ts`](../tests/form-fill-heldout.ts)
- 原始結果（每題輸入、模型原始輸出、最後的值與每欄對錯）：
  - [手機 LFM3 原題組](form-fill-eval-phone-lfm3-2026-11-07.json)
  - [手機 LFM3 保留題](form-fill-eval-phone-lfm3-heldout-2026-11-07.json)
  - [Mac qwen3 原題組](form-fill-eval-mac-qwen3-2026-11-07.json)
- 測試日期：2026-11-07～08

## 方法

**題組**

| 題組   | 表單                                                         | 題數 | 現有 function                          |
| ------ | ------------------------------------------------------------ | ---: | -------------------------------------- |
| 原題組 | 有話要說（陳情）：主旨、描述、地點、行政區                   |   20 | 規則 `draftReport`                     |
| 原題組 | 復康巴士預約：上下車地點、日期、時間、輪椅、陪同人數         |   16 | 無                                     |
| 保留題 | 有話要說（陳情）                                             |   12 | 規則 `draftReport`                     |
| 保留題 | 復康巴士預約                                                 |   12 | 無                                     |
| 保留題 | **無障礙導覽預約**：場館、日期、時間、人數、手語導覽、借輪椅 |   12 | 無，評測前沒有任何程式或題目碰過這張表 |

防護是看著原題組的錯誤設計的，所以另外請一個**沒看過防護程式與原題組**的代理撰寫保留題。保留題的「今天」也換成 2026-11-12（週四），會員地址也換了一個。保留題的分數才是結論的依據。

題目涵蓋：

- 一般說法、口語贅詞、錯字（路登、家理、輪倚）、英文
- 「我家」要帶會員地址、相對日期、只說「下午」沒有確切時間、否定（不用輪椅）
- 每張表一題提示注入

沒說到的欄位必須留空。

**條件**（輸出都經過同一個型別檢查 `validateValues`，用同一套評分）

| 條件                           | 說明                                                                                              |
| ------------------------------ | ------------------------------------------------------------------------------------------------- |
| rule                           | 現有規則 `draftReport`，只有陳情表有                                                              |
| dedicated                      | 專用 function：手寫的專用工具（各欄位有說明）、專用提示、兩個範例                                 |
| generic                        | **遮掉 function**：只有一個通用的 `fill_form`，表單欄位當資料傳入，沒有範例                       |
| generic-shot                   | generic 加一個「別張表」的範例                                                                    |
| dedicated+guard、generic+guard | 同一份模型輸出，再套上防護（不另外推論）                                                          |
| **guarded**                    | **最終方案** `fillFormGuarded`：先刪掉注入句，再用 generic 的提示詞，最後套防護。在手機上實際推論 |
| guarded-compact                | 另一版提示詞（日期留原話、不給表單名稱與會員地址）＋防護。數字較差，不採用                        |

**評分**：

- 地點、日期、時間、是否、人數：要符合可接受答案之一。地點可省略開頭的行政區，因為表單另有行政區欄。
- 主旨、描述：用關鍵字判斷，且不能含有注入的內容。
- 「捏造」＝應該留空的欄位被填了值；「漏填」＝民眾有說但沒填。

**模型**：

- 主要結果：手機上的 **`lfm3-1.7b-q4_0`**（Pixel 10 Pro XL，App 實際使用的接點），用 `node scripts/form-fill-phone.js` 跑。
- 對照：Mac Ollama 的 `qwen3:1.7b`。
- temperature 0，每題跑一次。

## 1.7B 模型自己會犯的錯，以及防護怎麼處理

| 模型的問題（遮掉 function 時）                                | 防護做法（每種欄位型別一條規則，不按表單寫）                                                                                                      |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **沒說的欄位不肯留空**：輪椅填 yes、人數填 0 或 1、日期填今天 | 是否／人數欄位：原話裡要有相關字眼才保留。字眼取自欄位標籤，可另外宣告 `cues`；人數欄也接受「N 人／位」。地點與名稱：值必須是原話的一段，否則清空 |
| **相對日期算錯**：「明天」填成今天或 11/02                    | 日期由程式從原話解析：明天、後天、大後天、下週一、這週日、11月20號、11/12、tomorrow、next Monday                                                  |
| **時間亂補**：只說「下午」卻填 13:00                          | 時間由程式解析：下午三點、九點半、早上，七點、2:30 pm；只有「下午」就留空                                                                         |
| **提示注入成功**：主旨填「市長下台」、日期填 2030 年          | 送給模型前，先刪掉含「忽略／無視／ignore…」的句子；值若只出現在被刪掉的句子裡，就拒絕                                                             |
| **主旨抄表單名稱**：「有話要說（陳情）」                      | 摘要欄位若是表單名稱、欄位標籤或提示文字，就改用原話的第一句                                                                                      |
| **「家」沒換成地址，或沒提到家卻填了會員地址**                | 「家／我家／家門口」換成會員地址，前提是原話有提到家；沒提到家卻填了會員地址就清空                                                                |
| **行政區亂猜**（中正區、文山區）                              | 行政區必須出現在原話或已填的地點裡；沒選但地點裡有，就自動帶入                                                                                    |
| **輸出被截斷**（陣列格式超過 256 tokens）                     | 不報錯，退回只用程式從原話讀出的值                                                                                                                |

防護不會發明任何值。值要嘛來自民眾的原話或會員地址，要嘛留空讓民眾填。

## 還沒解決的

- **人數語意**：「就我一個人」的陪同人數應為 0，模型常填 1；「我們三個人」模型常留空。陪同人數在保留題只有 50%，參觀人數 67%。最好在確認卡上把人數欄標為「請確認」。
- **行政區用前兩字判斷**：模型填「中山區」，因為原話有「中山北路」。目前用前兩字比對會放行，所以保留題陳情表仍有 1/3 捏造。
- **嚴重錯字**：「輪倚」「手勇導覽」對不上字眼，該欄會被清空（漏填，不是填錯）。
- **英文表單值**：英文請求的人數、手語等欄位常被留空。
- **延遲**：手機上 guarded 的中位延遲是 14～18 秒，專用工具是 4～9 秒。通用填表要送整張表的欄位，輸出也比較長。
- **確認卡仍然必要**：整張全對在保留題是 42～83%。

## 建議

1. **新表單**用 `fillFormGuarded`：宣告欄位清單（`FormSpec`）即可；摘要／描述欄位標 `kind`，是否／人數欄位視需要加 `cues`。仍要經確認卡，讓民眾逐欄確認。
2. **不要用跨表單範例**：模型會照抄範例的值，陳情表 generic-shot 只有 62.5%。
3. **陳情表**：
   - 現在的規則 `draftReport` 已修正地點擷取問題：
     - 「是信義區市府路」→「信義區市府路」
     - 「舉內湖區成功路四段」→「內湖區成功路四段」
     - 「北投區的溫泉路」→「北投區溫泉路」
     - 也支援「夜市」
   - 但在保留題上規則只有 81.3%，guarded 有 95.8%。之後可以考慮改由 guarded 填，只是延遲多約 10 秒。
4. **既有的專用 function** 也可以套 `guardValues`：復康巴士保留題 63.9% → 81.9%，捏造 4/10 → 0。

## 重現

```sh
# Mac Ollama（預設 qwen3:1.7b）
pnpm test:model tests/form-fill.eval.ts
# 手機：App 開著安心助手頁、adb reverse tcp:5173 tcp:5173
node scripts/form-fill-phone.js
# 保留題、只跑部分條件
FORM_EVAL_SET=heldout FORM_EVAL_CONDITIONS=rule,generic,generic+guard,guarded node scripts/form-fill-phone.js
# 改了防護或評分後，用已存的模型輸出重新評分（不推論；x+guard 與 guarded 會重新套防護）
FORM_EVAL_RESCORE=docs/form-fill-eval-phone-lfm3-2026-11-07.json \
  FORM_EVAL_CONDITIONS=rule,dedicated,dedicated+guard,generic,generic+guard,guarded \
  MODEL_NAME=lfm3-1.7b-q4_0 pnpm test:model tests/form-fill.eval.ts
```

## 限制

- 每種條件每題只跑一次（temperature 0）；題數少（原題組 36 題、保留題 36 題），差距在 5 個百分點以內的不宜過度解讀。
- 主旨與描述用關鍵字評分，比人工評分寬鬆。
- 保留題由另一個模型代理撰寫，沒有經過真人審題。
- 防護規則在看到保留題結果之前就已定案，之後沒有再改。截斷退回與贅詞處理是看原題組的錯誤加上的，也在保留題結果出來之前。
- 但「用哪一版提示詞」是在第一輪保留題結果出來後才選的：compact 與 form 兩版在兩個題組都量過，form 版在原題組也比較好。所以 guarded 的保留題分數，包含一次「從兩個已量測的設定中二選一」的選擇。

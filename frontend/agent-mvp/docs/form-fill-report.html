1.7B 模型能不能替新表單填資料？

手機 LFM3 1.7B（Pixel 10 Pro XL）實測 · 分支 feat/form-fill-eval（基於 PR 26）· commit a6ed3ab

只靠模型不夠，加上防護就可以。

把原本的規則函式 draftReport 遮掉、只靠模型時，新表單大約七成欄位正確，而且會自己編沒說過的值。我們在模型後面加了一層「按欄位型別檢查」的程式。新表單只要列出欄位就能直接套用，正確率升到近九成，也不再編造。

有規則函式 vs 遮掉規則函式

只有「有話要說（陳情）」有規則函式 draftReport（PR 26 的原始版本）。同一張表、同一批題目，比較有它和把它遮掉的差別：

陳情表的做法 原題組（20 題） 新題目（12 題）
原本的規則函式 92.5%（全對 75%） 79.2%（全對 33%）
遮掉規則，只靠模型 81.3%（全對 40%） 85.4%（全對 58%）
遮掉規則，模型＋防護 91.3%（全對 70%） 95.8%（全對 83%）
  • 在規則當初就是照著寫的題目上，遮掉規則會少 11 個百分點。
  • 換成沒看過的說法，規則掉到 79.2%，反而比只靠模型低。規則常把多餘的字抓進地點（「想反映中山北路二段」「就是大安森林公園」），也看不懂英文和「回家的巷子」。
  • 規則的優點是從不亂填（0 次）。模型加上防護後，也做到這點，兩個題組都和規則一樣好或更好。

模型會犯什麼錯，防護怎麼擋

1.7B 模型的錯 防護做法
沒說的欄位不肯留空（輪椅填 yes、人數填 0） 原話裡要有相關字眼（輪椅、陪…）才保留；地點必須是原話的一段
相對日期算錯（「明天」填成今天） 日期由程式從原話解析：明天、後天、下週一、11月20號、tomorrow…
只說「下午」卻填 13:00 時間由程式解析；沒有確切時間就留空
提示注入（主旨填「市長下台」） 送給模型前，先刪掉「忽略規則…」這類句子
主旨照抄表單名稱「有話要說（陳情）」 主旨若是表單名稱或欄位標籤，改用民眾原話的第一句
「家」沒換成地址，或沒提到家卻填了地址 有提到家才換成會員地址；沒提到就清空
行政區亂猜 行政區要出現在原話或地點裡才保留
輸出太長被截斷，整題失敗 不報錯，退回只用程式從原話讀出的值

防護不會自己發明值。每個值要嘛來自民眾說的話（或會員地址），要嘛留空讓民眾填。

新表單怎麼用

列出欄位就好，不用替它寫規則函式：

import { fillFormGuarded, type FormSpec } from './agent/skills/form-fill';

const TOUR_FORM: FormSpec = {
  id: 'accessible_tour_booking',
  title: '無障礙導覽預約',
  fields: [
    { id: 'venue', label: '參觀場館', type: 'text' },
    { id: 'date', label: '參觀日期', type: 'date' },
    { id: 'time', label: '入場時間', type: 'time' },
    { id: 'visitors', label: '參觀人數', type: 'count' },
    { id: 'sign_language', label: '是否需要手語導覽', type: 'yesno' },
  ],
};

const { values } = await fillFormGuarded(model, TOUR_FORM, 原話, {
  context: { today: '2026-11-12', memberAddress: 會員地址 },
});
// values 一律先放進確認卡，讓民眾逐欄確認後才送出
  • 欄位型別：text（地點、名稱）、district、date、time、yesno、count。
  • 主旨這類要模型寫的短句標 kind: 'summary'，描述標 kind: 'longtext'。
  • 是否／人數欄位的判斷字眼預設取自標籤；不夠時可加 cues，例如 ['輪椅', 'wheelchair']。

民眾講到一半改口

例如「台北車站，不對，是松山車站」「下午兩點，我是說三點」「我太太會陪我，啊她那天沒空」。原本的流程遇到改口，8 題只對 1 題，1.7B 模型幾乎都抓第一次說的值。

  • 防護認得改口：偵測「不對、我是說、更正、喔不、沒空…」。有改口時，日期、時間、行政區、是否欄位取最後的說法，被「不是…」否定的值不算。這部分是程式，不會變慢。
  • 審核 LLM：偵測到改口才請模型再看一次「最後的說法」。只在有主旨、描述這類自由文字的表單開啟。

  • 還做不好的：地點改口（60%）、沒說「不對」的隱性改口（78%），例如「我跟太太一起，不過她那天要上班」。確認卡要把被改過的欄位標出來，請民眾確認。

台北通的每一張表單都能用嗎？

把台北通站內每個要輸入資料的頁面都列成表單定義，共 18 張，另請沒看過程式的代理出了 90 題。查 YouBike、找廁所這類查詢不是填表，不在這次範圍。

表單（手機 LFM3＋防護） 欄位正確率
公司／商業登記費、地政規費、醫療費、快閃購、繳費編號 100%
停車費、圖書館查詢、市政訊息訂閱 90%
線上報案（案件）、繳費紀錄、土石流通報 83～88%

交通違規申訴、購票、路燈通報 64～72%
水費、災情通報（一般） 57～60%
合計 90 題 79.0%（整張全對 55/90）
  • 不是每個功能都能完美做到。繳費類的號碼欄位已經可以直接用；大多數表單在 80～90%，要搭配確認卡。
  • 對照：同一批題目只靠模型（Mac qwen3）是 50.0%，加防護 83.5%。
  • 做不好的：災情分類（20%）、地點描述被填成整句、路燈「不亮幾盞」、「地址就寫我家」沒拆成縣市／區／路名、肇事日期被算成明年、購票數量改口。
  • 為此新增下拉、多選、手機、市話、Email、編號、證號、車牌、數量等欄位型別，以及民國年、昨天／上週等日期說法。
  • 79.0% 包含跑完後才修的通用 bug，修正前是 77.7%，數字偏樂觀。

補強之後

針對上面做不好的地方補了五項：會員地址拆成縣市／區／路名、過去日期往前算、數量從線索字旁讀取（含改口）、災情分類同義詞、地點描述只收說明位置的短句。驗證用另一個代理新寫的 46 題，它沒看過程式和表單定義。

還要注意的

問題 現況 建議
人數語意 50～67% 「就我一個人」的陪同人數常被填成 1 確認卡上把人數欄標成「請確認」
整張全對 42～83% 確認卡必須保留，不能直接送出
速度 14～18 秒 規則函式不用推論，幾乎 0 秒 畫面要顯示「正在整理」的進度
嚴重錯字 「輪倚」對不上字眼，欄位會留空 留空讓民眾補填，不會填錯
陳情表 已修 規則函式在新題目上原本 79%，修正地點擷取後 81% 可考慮改用模型＋防護（95.8%），代價是多約 10 秒

怎麼測的

  • 題目：第一批 36 題（陳情 20、復康巴士 16），以及另寫的 36 題保留題（陳情、復康巴士、無障礙導覽各 12）。題目含口語贅詞、錯字、英文、「我家」、相對日期、否定，每張表一題提示注入。
  • 評分：每個欄位對照可接受答案；沒說的欄位必須留空。主旨、描述用關鍵字判斷。
  • 模型：App 內實際用的手機模型 lfm3-1.7b-q4_0，temperature 0，每題跑一次；Mac 的 qwen3:1.7b 為對照。
  • 限制：題數少，差距 5 個百分點以內不要過度解讀。保留題由另一個 AI 代理撰寫，沒有經過真人審題。
